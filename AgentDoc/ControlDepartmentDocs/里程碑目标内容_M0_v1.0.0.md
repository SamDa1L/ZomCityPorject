## 0. 文档用途与依据

- 用途：将 M0 里程碑目标固化为可执行、可验收、可回归的跨部门输入基线。
- 依据文档：

- 适用范围：M0 规划、拆分、执行、验收与收口全过程。

## 1. 核心目的

M0 的目标不是堆内容，而是把“工程底座”一次钉稳，确保后续 M1-M7 在不推翻底层合同的前提下迭代。

M0 完成后必须具备：

1. 2.5D 像素化渲染链路稳定可回归。
2. 输入采样、物理更新、相机与射击消费顺序稳定一致。
3. 最小角色控制与最小射击可复测，且事件链可观测。
4. 测试场景、门禁证据、回归路线形成闭环。

## 2. 协作部门与配合事项

- 需要配合部门：策划、程序、美术、QA。
- 配合事项与期望节点：
  - 策划（Design）：提交 M0 总需求分析与拆分需求，明确数据主键、规则口径、文档映射；节点为 `DesignAnalysis`、`RequirementSplit`。
  - 程序（Engineering）：落实 M0 产出 1-10，实现底座链路并沉淀门禁证据；节点为 `DepartmentExecuting`。
  - 美术（Art）：提供 M0 可验收最小资源（假人/占位怪/基础场景资产与标识资源），保障测试链路可跑通；节点为 `DepartmentExecuting`。
  - QA（Quality）：按 M0 固定回归路线执行终验并输出逐步化报告；节点为 `QAAccepted`。
- 时限口径：按 `AGENT_WORKFLOW_v1.0.md` 第 4.6 节 SLA 执行。

## 3. 阶段划分（里程碑主链）

### 阶段 A：目标确认与分析

- 状态：`MilestoneProposed -> DesignAnalysis -> ControlReviewed -> OwnerApproved`
- 输出：策划总分析、总控审核结论、项目负责人终审结论。

### 阶段 B：需求拆分与部门计划

- 状态：`RequirementSplit -> DepartmentPlanned`
- 输出：拆分需求文档、各部门执行计划文档。

### 阶段 C：部门执行与证据沉淀

- 状态：`DepartmentExecuting`
- 输出：部门工作结束汇报、门禁报告、风险跟踪记录。

### 阶段 D：三层验收与收口

- 状态：`DesignAccepted -> QAAccepted -> OwnerFinalAccepted -> MilestoneDone`
- 输出：策划验收结论、QA 最终验收报告、项目负责人终验结论。

### 4.2 非本里程碑范围（Out of Scope）

## 5. 验收标准（DoD）

### 5.1 M0 结果验收标准

1. 2.5D 链路稳定：无明显像素抖动，UI 清晰，准星/弹道/命中一致。
2. Gameplay Plane 稳定：持续跑跳/翻滚/受击/掉落 60 秒后玩法对象 Z 不漂移。
3. IntegerScale 与 DisplayRect 生效：16:9/16:10、窗口缩放、全屏切换下 AimPoint 一致。
4. 最小动作链稳定：走/跑/跳/蹲/蹲走/翻滚/受击硬直稳定，黑边 AimPoint clamp 不跳变。
5. PixelSnap 与插值生效：镜头平滑与偏移开启时无明显 jitter，波动帧率下角色与镜头无明显抖动。
6. 小窗口与奇数尺寸回归通过：DisplayRect 有效（`scale>=1`），无 0.5 像素游走。
7. 事件可观测：事件查看器能看到关键事件（含 Damage/Noise）。
8. LayerMatrix 固化：地面检测、落地事件、单向平台规则稳定。

### 5.2 M0 可测阈值（写死）

1. AimPoint 误差：窗口缩放/全屏切换后，同一屏幕点命中偏差 `<= 1 RT 像素`。
2. Pixel Jitter：角色静止、镜头平滑开启、鼠标缓慢摆动 30 秒，轮廓漂移 `<= 1 RT 像素`。
3. GC 阈值：武器测试场连续射击 60 秒，单帧 GC Alloc 峰值 `<= 1KB`，无周期性尖刺。
4. 帧时间阈值：目标机型下 95th percentile 帧时间 `<= 20ms`（约 50FPS）。

### 5.3 门禁验收标准

进入里程碑收口前必须至少具备：

1. DocGate 报告。
2. DataValidator 报告（含 PrefabKey 校验结果）。
3. 测试报告（EditMode/PlayMode/Smoke 对应范围）。
4. QA 最终验收报告（逐步化复现步骤）。

## 6. 风险与回滚

### 6.1 主要风险

1. 底座合同未钉死即推进上层功能，导致 M1 大规模返工。
2. 输入采样、物理、相机、射击消费顺序不一致，出现偶发错帧。
3. 映射口径多实现，造成 AimPoint 与命中偏差。
4. 证据链不完整，导致 ReadyForMerge 不可审计。

### 6.2 风险应对

1. 所有 M0 任务必须绑定到产出 1-10 条目，禁止“无归属开发”。
2. 每日 10:00/18:00 输出状态、阻塞与门禁清单。
3. 关键链路（渲染/输入/Tick/AimPoint）变更必须先跑固定回归路线再合并候选。
4. Warning 必须进入 `RiskFollowups` 并给出关闭截止日期。

### 6.3 回滚策略

- 任一关键 DoD 不满足时：
  1) 回退至 `DepartmentExecuting` 整改；
  2) 必要时回退 `DepartmentPlanned` 重排计划；
  3) 保留最近可运行稳定基线，不在坏状态叠加改动；
  4) 总控更新风险记录与影响面通报。

## 7. 操作步骤（总控执行版）

1. 以本文件发起 M0 里程碑卡，状态置为 `MilestoneProposed`。
2. 下发策划：2 个工作日内提交《里程碑总需求分析_M0》。
3. 1 个工作日内完成总控审核（通过/退回）并记录结论。
4. 提交项目负责人终审，未通过则退回策划重提。
5. 审批通过后推进拆分需求与部门执行计划，锁定依赖顺序与关键资产。
6. 执行阶段按产出 1-10 建立任务映射，跟踪证据生成进度。
7. 组织策划符合性验收 -> QA 终验 -> 项目负责人终验。
8. 项目负责人确认达标后，里程碑状态置为 `MilestoneDone`。
